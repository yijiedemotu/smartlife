## 阶段 0 · 服务器彻底清空

> 目的：从零开始，避免上次残留的容器/数据卷（尤其是按旧 `.env.prod` 初始化的 MySQL 密码）干扰验证。

```bash
cd /opt/smartlife 2>/dev/null || cd /opt
echo "=== 清空前状态 ==="
docker ps -a --format 'table {{.Names}}\t{{.Status}}' || true
docker volume ls | grep -E 'smartlife' || true

# 停止并删除容器 + 数据卷（数据全丢，演示环境无损失）
docker compose --env-file .env.prod -f docker-compose.prod.yml down -v 2>/dev/null || true
docker rm -f smartlife-mysql smartlife-redis smartlife-rabbitmq smartlife-backend smartlife-frontend 2>/dev/null || true
docker volume rm smartlife-mysql-data smartlife-redis-data smartlife-rabbitmq-data smartlife-backend-logs 2>/dev/null || true

echo "=== 清空后状态（必须为空）==="
docker ps -a --format 'table {{.Names}}\t{{.Status}}'
docker volume ls | grep -E 'smartlife' && echo "!! 仍有残留数据卷" || echo "OK：无 smartlife 残留数据卷"
```

**✅ 通过标准**
1. 结尾输出 `OK：无 smartlife 残留数据卷`
2. `docker ps -a` 里没有 `smartlife-*` 容器（表格只有表头也算通过）

**❗失败时请贴给我**：`docker ps -a` 和 `docker volume ls` 的完整输出。

## 阶段 2 · 拉取正确的代码

> 关键：这一步会校验"代码版本是否正确 + 构建上下文是否完整"，也就是上次失败的两个根因
> （旧代码缺 `settings.xml`、`.dockerignore` 把它排除了）。

```bash
cd /opt
# 若已有旧目录先备份掉（保留 .env.prod 不必要，阶段 3 会重新生成）
[ -d /opt/smartlife ] && mv /opt/smartlife /opt/smartlife.old.$(date +%s)

git clone https://github.com/yijiedemotu/smartlife.git smartlife
cd /opt/smartlife

echo "=== 2.1 当前代码版本（应为 819afb3 或更新）==="
git log --oneline -1
echo "  —— 期望看到 819afb3 chore: 新增 .gitattributes 强制部署关键文件以 LF 存储"

echo "=== 2.2 关键文件清单（每一项都必须输出文件名，不能报错）==="
for f in docker-compose.prod.yml .env.prod.example backend/Dockerfile backend/settings.xml \
         backend/.dockerignore frontend/Dockerfile frontend/nginx.conf \
         sql/init.sql scripts/deploy.sh scripts/backup-db.sh; do
  if [ -f "$f" ]; then echo "  [OK]   $f"; else echo "  [缺失] $f"; fi
done

echo "=== 2.3 .dockerignore 是否误排除了 settings.xml（必须无输出）==="
grep -n '^settings\.xml$' backend/.dockerignore && echo "!! 被排除了，需要删除该行" || echo "OK：未排除 settings.xml"

echo "=== 2.4 Dockerfile 的 COPY 源与磁盘文件是否一致 ==="
grep -nE '^COPY ' backend/Dockerfile | head -5
ls -l backend/settings.xml

echo "=== 2.5 脚本可执行位（应为 -rwxr-xr-x；若为 -rw- 则下面 chmod 修复）==="
chmod +x scripts/*.sh
ls -l scripts/*.sh

echo "=== 2.6 脚本换行格式（必须不含 CR，即不能是 CRLF）==="
if grep -lU $'\r' scripts/*.sh >/dev/null 2>&1; then
  echo "  !! 检测到 CRLF，修复中..."
  sed -i 's/\r$//' scripts/*.sh
  echo "  已修复为 LF"
else
  echo "  OK：scripts/*.sh 为 LF（无 CR）"
fi
# 再确认一次（应无输出）
grep -lU $'\r' scripts/*.sh && echo "  !! 仍有 CRLF" || echo "  二次确认通过"
# 顺便确认 shebang 后面没有多余字符
head -1 scripts/deploy.sh | cat -A | head -1

echo "=== 2.7 deploy.sh 占位符校验正则（新版应含 PLACEHOLDER_RE）==="
grep -n 'PLACEHOLDER_RE' scripts/deploy.sh || echo "（旧版脚本无此行，见下方说明）"
```

**✅ 通过标准**
1. 2.2 全部显示 `[OK]`，**没有 `[缺失]`**
2. 2.3 输出 `OK：未排除 settings.xml`
3. 2.5 脚本权限为 `-rwxr-xr-x`
4. 2.6 输出 `OK：scripts/*.sh 为 LF（无 CR）` + `二次确认通过`，且 `cat -A` 显示的 shebang 行**末尾是 `$` 而不是 `^M$`**
5. 2.7 能 grep 到 `PLACEHOLDER_RE`

**❗失败时请贴给我**：2.1 ~ 2.7 的完整输出。

> 说明：2.7 若显示"旧版脚本无此行"不影响部署能否跑通（只是 `deploy.sh` 的占位符校验会误报注释行）。
> 该修复目前只在你本机未推送。你可以选择：
> - **先跳过**，用 `docker compose ... up -d --build` 直接部署（阶段 4、5 都用这条命令，不依赖 deploy.sh）
> - 或让我把它推送上去，之后再 `git pull`

## 阶段 3 · 生成并校验密钥

```bash
cd /opt/smartlife
cp .env.prod.example .env.prod

# 生成随机密钥并直接写入（幂等：整行替换）
sed -i "s|^MYSQL_ROOT_PASSWORD=.*|MYSQL_ROOT_PASSWORD=$(openssl rand -base64 24)|" .env.prod
sed -i "s|^REDIS_PASSWORD=.*|REDIS_PASSWORD=$(openssl rand -base64 24)|" .env.prod
sed -i "s|^RABBIT_PASSWORD=.*|RABBIT_PASSWORD=$(openssl rand -base64 24)|" .env.prod
sed -i "s|^JWT_SECRET=.*|JWT_SECRET=$(openssl rand -base64 36)|" .env.prod
chmod 600 .env.prod

echo "=== 3.1 未替换的占位符（必须无输出）==="
grep -nE '^[ \t]*[A-Za-z_][A-Za-z0-9_]*=.*CHANGE_ME' .env.prod && echo "!! 仍有占位符" || echo "OK：无占位符残留"

echo "=== 3.2 四个密钥都已写入（只显示长度，避免泄屏）==="
awk -F= '/^(MYSQL_ROOT_PASSWORD|REDIS_PASSWORD|RABBIT_PASSWORD|JWT_SECRET)=/ {printf "  %-22s 长度=%d\n", $1, length($2)}' .env.prod

echo "=== 3.3 文件权限（应为 -rw-------）==="
ls -l .env.prod

echo "=== 3.4 密码备份到文件（供你之后抄走，验证完可删）==="
grep -E '^(MYSQL_ROOT_PASSWORD|REDIS_PASSWORD|RABBIT_PASSWORD|JWT_SECRET)=' .env.prod | tee /root/smartlife-secrets.txt
chmod 600 /root/smartlife-secrets.txt

echo "=== 3.5 compose 能否正确解析（应打印出服务名，且密钥已代入）==="
docker compose --env-file .env.prod -f docker-compose.prod.yml config --services
docker compose --env-file .env.prod -f docker-compose.prod.yml config | grep -c 'CHANGE_ME' | \
  sed 's/^/  config 中 CHANGE_ME 出现次数（应为 0）：/'
```

**✅ 通过标准**
1. 3.1 输出 `OK：无占位符残留`
2. 3.2 四行都显示 `长度=32` 或 `长度=48`（base64 24/36 字节的结果），**没有长度=0**
3. 3.3 显示 `-rw-------`
4. 3.5 打印出 5 个服务名：`mysql redis rabbitmq backend frontend`；CHANGE_ME 次数为 `0`

**❗失败时请贴给我**：3.1~3.5 输出（**密钥本身请打码**，我只需要看长度和格式）。

## 阶段 5 · 启动服务

```bash
cd /opt/smartlife
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d

echo "=== 5.1 等待中间件与后端就绪（最多 120 秒）==="
for i in $(seq 1 24); do
  sleep 5
  RUNNING=$(docker compose --env-file .env.prod -f docker-compose.prod.yml ps --format '{{.Service}} {{.State}}' | grep -c 'running')
  READY=$(docker compose --env-file .env.prod -f docker-compose.prod.yml ps --format '{{.Service}} {{.Health}}' | grep -c 'healthy')
  echo "  第 $((i*5)) 秒：running=$RUNNING healthy=$READY"
  [ "$RUNNING" -ge 5 ] && [ "$READY" -ge 3 ] && break
done

echo "=== 5.2 最终状态 ==="
docker compose --env-file .env.prod -f docker-compose.prod.yml ps

echo "=== 5.3 端口暴露检查（关键：只有 frontend 应为 0.0.0.0）==="
docker compose --env-file .env.prod -f docker-compose.prod.yml ps --format '{{.Service}}\t{{.Ports}}'

echo "=== 5.4 后端启动日志（应含 Started SmartLifeApplication）==="
docker compose --env-file .env.prod -f docker-compose.prod.yml logs --tail=15 backend
```

**✅ 通过标准**

| 检查 | 期望 |
|---|---|
| 5.2 | 5 个容器全部 `Up`；mysql/redis/rabbitmq 为 `(healthy)`；backend 可能显示 `(health: starting)`，等 1 分钟再看 |
| 5.3 | **只有 frontend 是 `0.0.0.0:80->80/tcp`**；backend `127.0.0.1:8080`；mysql `127.0.0.1:3306`；redis `127.0.0.1:6379` |
| 5.4 | 出现 `Started SmartLifeApplication in ... seconds` 与 `索引初始化完成：布隆过滤器 + GEO 装载 10 家可展示店铺` |

## 阶段 7 · 加固与备份（可选，验收通过后再做）

> ⚠️ **重要前提**：`MYSQL_ROOT_PASSWORD` 只在数据卷**第一次初始化**时生效。

## 失败排查速查（先自查，再贴给我）

| 症状 | 先看这里 |
|---|---|
| `couldn't find env file: /root/.env.prod` | 工作目录不对，先 `cd /opt/smartlife` |
| `./scripts/deploy.sh: Permission denied` | `chmod +x scripts/*.sh` 或用 `bash scripts/deploy.sh` |
| `"/settings.xml": not found` | 阶段 2.3：从 `backend/.dockerignore` 删掉 `settings.xml` 行 |
| `Killed` / 构建被打断 | 内存不足：确认 Swap ≥ 2G（阶段 1.3） |
| 登录报"服务器繁忙" | `sl logs --tail=60 backend` 找 ERROR；多为 MySQL 未就绪或密码不一致 |
| 浏览器打不开 | 先 `curl -I http://127.0.0.1/`：本机通就是**安全组没放行 80** |
| 改了 `.env.prod` 密码后连不上库 | 数据卷里是旧密码。要么改回，要么 `down -v` 后重新初始化 |
