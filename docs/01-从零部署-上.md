# 从零部署（上）· 阶段 0 ~ 5：把镜像准备好

> **这份文档假设你有一台全新的阿里云 ECS（Ubuntu 22.04，无域名），从空机器开始，一路做到"镜像已构建好、随时可启动"。**
> 下一份文档（`02-从零部署-下.md`）负责启动、验收与运维。
>
> **使用方式（重要）**
> 1. 一次只做一个阶段。
> 2. 每个阶段都是 **「执行 → 对照通过标准 → 通过后才进下一阶段」**。
> 3. 不通过就**停下**，用每个阶段末尾的「❗不通过就贴给我」命令取证，不要把失败带到下一阶段。
>
> 全程只有两个变量需要你替换：**公网 IP** 和（可选的）**部署目录**。下面所有命令都可直接整段复制，
> **没有任何尖括号占位符**，不会出现 `bash: ...: No such file or directory` 那种复制粘贴事故。

---

## 总览：五个阶段在干什么

| 阶段 | 在哪台机器做 | 干什么 | 通过标志 |
|---|---|---|---|
| 0 | 服务器 | 把机器恢复成"干净空机器" | 无容器、无数据卷 |
| 1 | 服务器 | 系统准备（时区 / Swap / Docker） | 5 项检查全绿 |
| 2 | **本地 Windows** | 打包部署包 | 生成 `smartlife-deploy-*.tar.gz` |
| 3 | 服务器 | 上传 + 解压 + 包完整性校验 | `FAIL=0` |
| 4 | 服务器 | 生成并写入密钥 | 无占位符残留、compose 可解析 |
| 5 | 服务器 | 构建后端 + 前端镜像 | 两个镜像 Built，容器内产物存在 |

```
本地 Windows                    阿里云 ECS (Ubuntu 22.04)
─────────────                   ──────────────────────────
阶段 2 打包  ──── scp 上传 ────►  阶段 3 解压 + 校验
                                  阶段 4 生成密钥
                                  阶段 5 构建镜像
                                  ↓（下一份文档）
                                  阶段 6~10 启动 / 验收 / 运维
```

# 阶段 0 · 把服务器清空

**目的**：消除历史残留。特别是 **MySQL 的 root 密码只在数据卷第一次初始化时生效**，
如果数据卷是上一次用旧 `.env.prod` 建的，这次换了密码就连不上库——所以必须清掉数据卷。

### 执行（整段粘贴）

```bash
echo "########## 清空前状态 ##########"
docker ps -a --format 'table {{.Names}}\t{{.Status}}' 2>/dev/null || echo "（docker 尚未安装，可忽略）"
docker volume ls 2>/dev/null | grep smartlife || echo "（无 smartlife 数据卷）"
ls -d /opt/smartlife 2>/dev/null || echo "（/opt/smartlife 不存在）"

echo
echo "########## 开始清理 ##########"
# 1) 停容器并删除数据卷
cd /opt/smartlife 2>/dev/null && docker compose --env-file .env.prod -f docker-compose.prod.yml down -v 2>/dev/null || true
# 2) 兜底：直接删容器
docker rm -f smartlife-mysql smartlife-redis smartlife-rabbitmq smartlife-backend smartlife-frontend 2>/dev/null || true
# 3) 兜底：直接删数据卷
docker volume rm smartlife-mysql-data smartlife-redis-data smartlife-rabbitmq-data smartlife-backend-logs 2>/dev/null || true
# 4) 删旧镜像（可选，能腾出约 1.5G 磁盘）
docker rmi smartlife-backend:2.0.0 smartlife-frontend:2.0.0 2>/dev/null || true
# 5) 旧代码目录挪走（不删，万一要回看；带时间戳避免覆盖）
cd /opt 2>/dev/null && [ -d smartlife ] && mv smartlife "smartlife.old.$(date +%s)" || true

echo
echo "########## 清空后状态（必须干净）##########"
docker ps -a --format 'table {{.Names}}\t{{.Status}}' 2>/dev/null | head -5
docker volume ls 2>/dev/null | grep smartlife && echo "!! 仍有 smartlife 数据卷" || echo "OK：无 smartlife 数据卷"
ls -d /opt/smartlife 2>/dev/null && echo "!! /opt/smartlife 仍存在" || echo "OK：/opt/smartlife 已清空"
```

### ✅ 通过标准

输出里必须同时出现这两行：

```
OK：无 smartlife 数据卷
OK：/opt/smartlife 已清空
```

并且 `docker ps -a` 的列表里**没有** `smartlife-` 开头的容器（只有表头也算通过）。

### ❗不通过就贴给我

```bash
docker ps -a
docker volume ls
ls -la /opt/
```

# 阶段 1 · 系统准备

**目的**：把 Ubuntu 22.04 调成能跑这套 5 容器栈的状态：时区正确（影响签到/秒杀按天统计）、有 Swap 兜底、
Docker 与 compose 插件可用。

### 1.1 安装基础工具 + 设置时区

```bash
apt-get update -y
apt-get install -y curl wget vim git unzip cron ca-certificates htop net-tools

timedatectl set-timezone Asia/Shanghai
```

### 1.2 添加 Swap（内存 ≤ 4G 必做）

> ⚠️ 判断后再建，避免"文件已存在又执行 `mkswap`"报 `Text file busy`（这是之前真实踩过的坑）。

```bash
if swapon --show | grep -q '/swapfile'; then
  echo "Swap 已存在，跳过创建"
else
  fallocate -l 2G /swapfile || dd if=/dev/zero of=/swapfile bs=1M count=2048
  chmod 600 /swapfile
  mkswap /swapfile
  swapon /swapfile
  grep -q '^/swapfile' /etc/fstab || echo '/swapfile none swap sw 0 0' >> /etc/fstab
fi
sysctl -w vm.swappiness=10
grep -q '^vm.swappiness' /etc/sysctl.conf || echo 'vm.swappiness=10' >> /etc/sysctl.conf
```

### 1.3 安装 Docker 与 compose 插件

```bash
if command -v docker >/dev/null 2>&1; then
  echo "Docker 已安装：$(docker --version)，跳过安装"
else
  curl -fsSL https://get.docker.com | bash -s docker --mirror Aliyun
fi
systemctl enable docker --now
```

### 1.4 配置镜像加速（可选，但强烈建议）

> 阿里云 ECS 直连 Docker Hub 经常很慢。加速地址在[容器镜像服务控制台](https://cr.console.aliyun.com/cn-hangzhou/instances/mirrors)能看到。

```bash
# 把 你的ID 替换成控制台给你的那串（形如 bk1in3op）
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://你的ID.mirror.aliyuncs.com"]
}
EOF
systemctl daemon-reload && systemctl restart docker
```

### 执行校验（整段粘贴）

```bash
echo "=== 1.1 系统版本 ==="
lsb_release -d 2>/dev/null || cat /etc/os-release | head -2

echo "=== 1.2 时区（应为 CST +0800）==="
timedatectl | grep -E 'Time zone|Local time'
date

echo "=== 1.3 内存与 Swap（Swap 应 >= 2.0Gi）==="
free -h

echo "=== 1.4 Docker 与 compose ==="
docker --version
docker compose version
echo "daemon 状态: $(systemctl is-active docker)"

echo "=== 1.5 磁盘剩余（应 >= 15G）==="
df -h / | tail -1

echo "=== 1.6 网络能否拉到镜像（试拉一个小镜像）==="
docker pull hello-world >/dev/null 2>&1 && echo "OK：镜像仓库可达" || echo "!! 拉取失败，检查镜像加速配置"
docker rmi hello-world >/dev/null 2>&1 || true
```

### ✅ 通过标准

| 项 | 期望 |
|---|---|
| 1.1 | `Ubuntu 22.04.x LTS` |
| 1.2 | `Time zone: Asia/Shanghai (CST, +0800)` |
| 1.3 | `Swap:` 行 ≥ `2.0Gi`；`Mem:` 的 available ≥ 1.0Gi |
| 1.4 | 两个版本号都打印出来，daemon 状态 `active` |
| 1.5 | 根分区 Available ≥ 15G |
| 1.6 | `OK：镜像仓库可达` |

### ❗不通过就贴给我

上面 1.1~1.6 中**失败那一段**的完整输出。

# 阶段 3 · 上传、解压、包完整性校验

**目的**：把包传到服务器，解压后由**包内自带的校验脚本**一次性检查：
文件是否齐全、换行是否 LF、脚本是否有执行位、`.dockerignore` 是否误排除 `settings.xml`、
Dockerfile 的 `COPY` 源是否都在。

### 3.1 上传（在你本机 PowerShell 执行）

```powershell
# 把 你的公网IP 换成真实 IP（不要加尖括号）
scp "D:\Projects\smartlife\smartlife-deploy-20260912-190042.tar.gz" root@你的公网IP:/root/
```

### 3.2 解压 + 校验（在服务器执行，整段粘贴）

```bash
cd /root
echo "=== 已上传的包 ==="
ls -lh smartlife-deploy-*.tar.gz || { echo "!! 没找到包，请先执行 3.1 上传"; exit 1; }

mkdir -p /opt/smartlife
tar -xzf "$(ls -t smartlife-deploy-*.tar.gz | head -1)" -C /opt/smartlife
cd /opt/smartlife

echo
echo "=== 3.1 解压后文件数（应约 185）==="
find . -type f | wc -l

echo
echo "=== 3.2 关键文件是否都在 ==="
for f in docker-compose.prod.yml .env.prod.example .gitattributes \
         backend/Dockerfile backend/settings.xml backend/pom.xml backend/.dockerignore \
         frontend/Dockerfile frontend/nginx.conf frontend/package.json \
         sql/init.sql scripts/deploy.sh scripts/verify-package.sh scripts/backup-db.sh; do
  if [ -f "$f" ]; then printf '  [ OK ] %s\n' "$f"; else printf '  [MISS] %s\n' "$f"; fi
done

echo
echo "=== 3.3 包完整性校验（--fix 会自动补执行位、清 CRLF）==="
bash scripts/verify-package.sh --fix
```

### ✅ 通过标准

| 项 | 期望 |
|---|---|
| 3.1 | 文件数 ≈ 185（±5 都正常） |
| 3.2 | 14 个文件全部 `[ OK ]`，**没有 `[MISS]`** |
| 3.3 | 结尾 `结果：PASS=… FAIL=0` 且 `✅ 部署包校验通过` |

> 3.3 里如果出现 `[WARN] .env.prod 尚未创建` 和 `[WARN] 未检测到 docker`，属**正常**（阶段 4 才建 `.env.prod`）。

### 3.4 收尾确认（可选但推荐）

```bash
cd /opt/smartlife
bash scripts/verify-package.sh | tail -6     # 不带 --fix 再跑一次，确认 FAIL=0
ls -l scripts/*.sh                            # 应全部是 -rwxr-xr-x
```

# 阶段 4 · 生成并写入密钥

**目的**：把 `.env.prod.example` 复制成 `.env.prod`，用随机值替换 4 个占位密码，并**验证替换干净**。

> ⚠️ 两个必须知道的规则：
> 1. **不要先手工 `openssl rand` 再拿随机串去 `sed` 替换** —— 模板里是 `CHANGE_ME_...` 占位符，
>    用随机串去匹配是匹配不到任何内容的（这是之前真实踩过的坑）。
> 2. **`MYSQL_ROOT_PASSWORD` 只在数据卷第一次初始化时生效**。阶段 4 定下来的密码，就是数据库最终密码；
>    之后再改 `.env.prod` 而不同时删数据卷，后端就连不上库。

### 执行（整段粘贴）

```bash
cd /opt/smartlife
cp .env.prod.example .env.prod

# 生成随机值并「整行替换」写入（幂等，重复执行会重新生成）
sed -i "s|^MYSQL_ROOT_PASSWORD=.*|MYSQL_ROOT_PASSWORD=$(openssl rand -base64 24)|" .env.prod
sed -i "s|^REDIS_PASSWORD=.*|REDIS_PASSWORD=$(openssl rand -base64 24)|" .env.prod
sed -i "s|^RABBIT_PASSWORD=.*|RABBIT_PASSWORD=$(openssl rand -base64 24)|" .env.prod
sed -i "s|^JWT_SECRET=.*|JWT_SECRET=$(openssl rand -base64 36)|" .env.prod
chmod 600 .env.prod

echo "=== 4.1 占位符残留检查（必须无输出）==="
grep -nE '^[ \t]*[A-Za-z_][A-Za-z0-9_]*=.*CHANGE_ME' .env.prod && echo "!! 仍有占位符未替换" || echo "OK：无占位符残留"

echo
echo "=== 4.2 四个密钥的长度（不显示明文，应为 32 或 48）==="
awk -F= '/^(MYSQL_ROOT_PASSWORD|REDIS_PASSWORD|RABBIT_PASSWORD|JWT_SECRET)=/ {printf "  %-22s 长度=%d\n", $1, length($2)}' .env.prod

echo
echo "=== 4.3 文件权限（应为 -rw-------）==="
ls -l .env.prod

echo
echo "=== 4.4 备份密钥到只读文件（方便你抄走，验收后建议删掉）==="
grep -E '^(MYSQL_ROOT_PASSWORD|REDIS_PASSWORD|RABBIT_PASSWORD|JWT_SECRET)=' .env.prod | tee /root/smartlife-secrets.txt
chmod 600 /root/smartlife-secrets.txt

echo
echo "=== 4.5 compose 能否正确解析（应打印 5 个服务名）==="
docker compose --env-file .env.prod -f docker-compose.prod.yml config --services

echo
echo "=== 4.6 配置里是否还残留占位符（应为 0）==="
docker compose --env-file .env.prod -f docker-compose.prod.yml config 2>/dev/null | grep -c 'CHANGE_ME' | sed 's/^/  CHANGE_ME 出现次数: /'
```

### ✅ 通过标准

| 项 | 期望 |
|---|---|
| 4.1 | `OK：无占位符残留` |
| 4.2 | 四行长度都是 `32` 或 `48`（**没有 `长度=0`**） |
| 4.3 | `-rw-------` |
| 4.5 | 依次打印 `mysql` `redis` `rabbitmq` `backend` `frontend` |
| 4.6 | `CHANGE_ME 出现次数: 0` |

### 4.7 把密码抄进你的密码管理器

```bash
cat /root/smartlife-secrets.txt
```

> 这一步的密码只用于你自己运维（连数据库、恢复备份）。**验收通过后可 `rm /root/smartlife-secrets.txt`。**

### ❗不通过就贴给我

# 阶段 5 · 构建镜像

**目的**：在容器内编译后端（Maven）与前端（Vite），产出两个镜像。**首次约 5~15 分钟。**

> 这一步是历史上最容易失败的环节，两个已知根因都已在代码里修掉：
> `backend/.dockerignore` 误排除 `settings.xml`、Windows 打包含 CRLF。阶段 3 的校验已确认这两点没问题。

### 执行（整段粘贴，建议放后台跑）

```bash
cd /opt/smartlife

# 后台构建并输出进度到日志，避免 SSH 断线中断等待
nohup docker compose --env-file .env.prod -f docker-compose.prod.yml build > /root/build.log 2>&1 &
echo "构建已在后台启动，日志：/root/build.log"

# 每 30 秒看一次进度（Ctrl+C 只是退出查看，不会中断构建）
for i in $(seq 1 40); do
  sleep 30
  if grep -qE 'ERROR|failed to solve' /root/build.log 2>/dev/null; then
    echo "!! 构建报错，请查看 /root/build.log"; break
  fi
  if [ "$(docker images -q smartlife-backend:2.0.0 | wc -l)" -ge 1 ] && \
     [ "$(docker images -q smartlife-frontend:2.0.0 | wc -l)" -ge 1 ]; then
    echo "两个镜像都已生成 ✅"; break
  fi
  echo "  第 $((i*30)) 秒：$(tail -1 /root/build.log 2>/dev/null | cut -c1-90)"
done
```

### 执行校验

```bash
cd /opt/smartlife

echo "=== 5.1 镜像列表 ==="
docker images | grep -E 'REPOSITORY|smartlife'

echo
echo "=== 5.2 后端镜像里是否真的有 jar ==="
docker run --rm --entrypoint sh smartlife-backend:2.0.0 -c 'ls -lh /app/app.jar'

echo
echo "=== 5.3 前端镜像里是否真的有静态产物 ==="
docker run --rm --entrypoint sh smartlife-frontend:2.0.0 -c 'ls /usr/share/nginx/html; echo "--- assets ---"; ls /usr/share/nginx/html/assets | head -3'

echo
echo "=== 5.4 构建日志里的关键信息 ==="
grep -E 'smartlife\]|settings.xml|BUILD SUCCESS|built in' /root/build.log | tail -8

echo
echo "=== 5.5 有无报错 ==="
grep -cE 'ERROR|failed to solve' /root/build.log | sed 's/^/  错误行数（应为 0）: /'
```

### ✅ 通过标准

| 项 | 期望 |
|---|---|
| 5.1 | 能看到 `smartlife-backend:2.0.0` 与 `smartlife-frontend:2.0.0` |
| 5.2 | 打印出 `/app/app.jar`（说明容器内 Maven 编译成功） |
| 5.3 | 打印出 `index.html` 与 `assets`（说明容器内 Vite 构建成功） |
| 5.4 | 能看到 `[smartlife] 使用仓库自带的 settings.xml`（或"已生成兜底配置"）与 `BUILD SUCCESS` |
| 5.5 | `错误行数（应为 0）: 0` |

```bash
tail -60 /root/build.log
```
