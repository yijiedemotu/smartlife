## 1. 部署前必读

### 1.1 服务器规格建议

| 项 | 最低 | 推荐 | 说明 |
|---|---|---|---|
| CPU/内存 | 2 核 2G（需加 2G Swap） | **2 核 4G** | 同时跑 5 个容器：MySQL 512M + RabbitMQ 300M + 后端 JVM 1G + Redis/Nginx 约 150M |
| 系统盘 | 40G ESSD | 60G ESSD | 镜像约 1.5G，MySQL 数据 + 日志会持续增长 |
| 带宽 | 1~3 Mbps | 3~5 Mbps | 首次拉取镜像/构建依赖较慢，构建完成后运行期占用很小 |
| 系统 | Ubuntu 22.04 LTS 64 位 | 同左 | 阿里云镜像市场默认即有此版本 |

> **成本提示**：如果只是演示，1~2 核 2G + 按量付费即可，但**必须加 Swap**（见第 3.3 节），否则 Maven 构建阶段容易 OOM 被杀。

### 1.2 部署架构（单机五容器）

```
                       公网
                        │  HTTP :80（安全组唯一放行端口）
                        ▼
        ┌──────────────────────────────────────────────────┐
        │  smartlife-frontend (nginx:1.25-alpine)          │
        │   · 托管 Vue3 打包产物（/user /merchant /admin）  │
        │   · /api/** 反向代理到 backend:8080               │
        │   · /api/ws WebSocket 升级                        │
        └───────────────┬──────────────────────────────────┘
                        │ Docker 内网 smartlife-net（服务名即 DNS）
                        ▼
        ┌──────────────────────────────────────────────────┐
        │  smartlife-backend (eclipse-temurin:17-jre)      │
        │   Spring Boot 2.7 · context-path=/api            │
        │   三端鉴权：/merchant/** · /admin/** · 用户端接口   │
        └───┬───────────────┬──────────────────┬───────────┘
            │               │                  │
            ▼               ▼                  ▼
     ┌───────────┐   ┌───────────┐     ┌──────────────┐
     │ mysql:8.0 │   │ redis:7   │     │ rabbitmq:3.12│
     │ 数据卷持久化 │   │ AOF 持久化 │     │ 秒杀削峰+死信 │
     └───────────┘   └───────────┘     └──────────────┘
       ↑ 首次启动自动执行 sql/init.sql（建表 + 三端种子数据）
```

### 1.3 关键设计（决定了后面为什么这么操作）

| 设计点 | 部署含义 |
|---|---|
| 只有 frontend 容器对外暴露 80 端口 | 安全组只需放行 80，数据库/中间件不对公网暴露 |
| MySQL/Redis/RabbitMQ 端口绑定 `127.0.0.1` | 需要本机调试时才用 SSH 隧道转发，见 10.4 |
| 后端镜像在**容器内**用 Maven 多阶段构建 | 服务器上**不需要安装 JDK / Maven**，只用 Docker |
| 首次启动自动执行 `sql/init.sql` | 只有 **mysql 数据卷为空时**才会执行，重新部署不会覆盖数据 |
| 所有密码/密钥通过 `.env.prod` 注入 | 改密码只需改这个文件 + `up -d`，不用改代码 |
| `SPRING_PROFILES_ACTIVE=prod` | 生产关闭 SQL 日志与 Knife4j 接口文档公网暴露 |

## 2. 第 1 步：阿里云控制台配置

### 2.1 放行安全组端口

1. 登录[阿里云 ECS 控制台](https://ecs.console.aliyun.com/) → 左侧「实例与镜像 / 实例」→ 找到你的实例。
2. 点实例 ID 进入详情 → 「安全组」→ 点击安全组 ID → 「访问规则」→「入方向」→「手动添加」。

按下表添加入方向规则（**只放行必要端口**）：

| 优先级 | 协议类型 | 端口范围 | 授权对象 | 用途 |
|---|---|---|---|---|
| 1 | 自定义 TCP | `22/22` | `0.0.0.0/0`（或你的办公 IP，更安全） | SSH 登录 |
| 1 | 自定义 TCP | `80/80` | `0.0.0.0/0` | 网站访问（唯一对外业务端口） |
| 1 | 自定义 TCP | `443/443` | `0.0.0.0/0` | 以后配 HTTPS 时用（现在可先不加） |
| 1 | ICMP | `-1/-1` | `0.0.0.0/0` | 允许 ping（可选） |

> ⚠️ **不要**放行 3306（MySQL）、6379（Redis）、5672/15672（RabbitMQ）、8080（后端）。本项目的 compose 已把这些端口绑到容器内网的 `127.0.0.1`，公网本来就访问不到，安全组再叠加一层更稳。

### 2.2 重置实例密码（如果不知道 root 密码）

实例详情 → 「更多」→「密码/密钥」→「重置实例密码」→ 设置强密码 → **重启实例**生效。

### 2.3 确认公网 IP

实例列表里「IP 地址」列的**公网 IP** 就是后面访问地址的主机名，例如 `47.98.123.45`。
本文后续用 `<你的公网IP>` 占位，请自行替换。

## 3. 第 2 步：SSH 登录并做基础初始化

### 3.1 登录服务器

在你本地电脑的终端（Windows 用 PowerShell / CMD）：

```bash
ssh root@<你的公网IP>
# 首次连接会提示 yes/no，输入 yes，然后输入刚才设置的密码
```

登录成功后提示符会变成 `root@iZbp****:~#`。

### 3.2 更新系统与安装基础工具

```bash
# 更新软件包索引并升级已有软件（首次可能耗时几分钟）
apt-get update && apt-get -y upgrade

# 安装常用工具：curl/wget 下载、vim 编辑、git 拉代码、unzip 解压、
# cron 定时备份、ca-certificates 证书、htop 看资源
apt-get install -y curl wget vim git unzip cron ca-certificates htop net-tools
```

### 3.3 设置时区为东八区（重要）

项目的签到（BitMap 按天）、秒杀时间窗、订单统计都按**东八区**计算，服务器时区错了业务日期就会错。

```bash
timedatectl set-timezone Asia/Shanghai
date          # 应显示 CST 时间，例如 Fri Sep 12 15:30:00 CST 2026
```

### 3.4 检查内存与磁盘

```bash
free -h        # 看 available 内存
df -h /        # 看根分区剩余空间（建议 >= 20G）
nproc          # 看 CPU 核数
```

## 4. 第 3 步：配置国内镜像源与 Swap

### 4.1 配置 Docker 镜像加速（阿里云服务器必备）

> 说明：直接在阿里云 ECS 上从 Docker Hub 拉镜像可能很慢甚至超时。使用阿里云容器镜像服务的加速地址可显著提速。

1. 打开[容器镜像服务控制台](https://cr.console.aliyun.com/cn-hangzhou/instances/mirrors)，登录后能看到**专属加速地址**（形如 `https://xxxx.mirror.aliyuncs.com`）。
2. 在服务器上写入 Docker 配置：

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://xxxx.mirror.aliyuncs.com"]
}
EOF
# 把上面 xxxx 换成你自己的加速地址
```

> 如果暂时拿不到专属地址，也可以先跳过这步，Docker 会自动走默认源；若拉取失败再回来配置。

### 4.2 配置 Maven 阿里云源（已内置，无需改）

后端镜像构建时会使用 `backend/settings.xml`（阿里云 Maven 仓库），无需你在服务器上额外配置。

### 4.3 添加 2G Swap（内存 ≤ 4G 强烈建议）

```bash
# 创建 2G swap 文件
fallocate -l 2G /swapfile || dd if=/dev/zero of=/swapfile bs=1M count=2048
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile

# 开机自动挂载
echo '/swapfile none swap sw 0 0' >> /etc/fstab

# 降低 swap 使用倾向（尽量用物理内存，swap 只兜底）
echo 'vm.swappiness=10' >> /etc/sysctl.conf
sysctl -p

free -h    # 确认 Swap 行有 2.0Gi
```

## 6. 第 5 步：把代码放到服务器

服务器是全新的，还没有代码。三种方式任选一种，**推荐方式 A**。

### 方式 A：从 Git 仓库拉取（推荐）

```bash
mkdir -p /opt && cd /opt
git clone <你的仓库地址> smartlife
cd /opt/smartlife
```

### 方式 B：本地打包上传（没有 Git 仓库时）

在**你本地电脑**项目根目录执行（注意先排除无需上传的产物）：

```powershell
# Windows PowerShell，在项目根目录（D:\Projects\smartlife\smartlife）
# 打包成 zip（排除 node_modules / target / dist / 日志，体积从数百 MB 降到几 MB）
$exclude = @('node_modules','target','dist','.git','.idea','backup')
Get-ChildItem -Force | Where-Object { $exclude -notcontains $_.Name } |
  Compress-Archive -DestinationPath smartlife-src.zip -Force
```

```bash
# 上传到服务器（在你本地终端执行）
scp smartlife-src.zip root@<你的公网IP>:/opt/
```

```bash
# 服务器上解压
cd /opt && apt-get install -y unzip   # 若第 3.2 步已装则跳过
unzip -q smartlife-src.zip -d smartlife
cd /opt/smartlife
ls    # 应看到 backend/ frontend/ sql/ scripts/ docker-compose.prod.yml 等
```

### 方式 C：用 MobaXterm / FinalShell 图形化上传

把整个项目目录拖到 `/opt/smartlife`，然后确认目录结构正确即可。

### 6.1 确认关键文件都在

```bash
cd /opt/smartlife
ls -1 docker-compose.prod.yml .env.prod.example backend/Dockerfile frontend/Dockerfile \
      frontend/nginx.conf sql/init.sql scripts/deploy.sh scripts/backup-db.sh
```

六七个文件都应存在且无报错。若某个缺失，说明上传/拉取不完整。

### 6.2 给脚本加执行权限

```bash
chmod +x scripts/*.sh
```

## 7. 第 6 步：配置生产环境变量 `.env.prod`

### 7.1 生成强随机密码

```bash
# 连续执行 5 次，每次生成一个不同的随机串，分别用于下面 5 个密码/密钥
openssl rand -base64 24
```

也可以直接用一条命令把模板里的 `CHANGE_ME...` 全部自动替换掉：

```bash
cd /opt/smartlife
cp .env.prod.example .env.prod

# 自动生成并替换密码（生成结果请立刻记录到你的密码管理器！）
sed -i "s|CHANGE_ME_mysql_root_strong_password|$(openssl rand -base64 24)|" .env.prod
sed -i "s|CHANGE_ME_redis_strong_password|$(openssl rand -base64 24)|" .env.prod
sed -i "s|CHANGE_ME_rabbitmq_strong_password|$(openssl rand -base64 24)|" .env.prod
sed -i "s|CHANGE_ME_jwt_secret_at_least_32_bytes_long_random_string|$(openssl rand -base64 36)|" .env.prod

# 查看并抄走这些密码（务必保存，后续备份恢复/连库都要用）
cat .env.prod
```

### 7.2 `.env.prod` 各变量含义

| 变量 | 说明 |
|---|---|
| `APP_VERSION` | 镜像 tag，发新版递增，便于回滚（如 `2.0.1`） |
| `HTTP_PORT` | 对外网站端口，默认 `80`；若被占用可改 `8081`（同时要改安全组） |
| `MYSQL_DATABASE` | 数据库名，默认 `smartlife` |
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码，容器内后端用它连库 |
| `REDIS_PASSWORD` | Redis 密码（Redis 7 默认无密码，本项目强制设置） |
| `RABBIT_USER` / `RABBIT_PASSWORD` | RabbitMQ 账号密码 |
| `JWT_SECRET` | JWT 签名密钥，**必须 ≥ 32 字节**；更换后所有用户需重新登录 |
| `SECKILL_LUA_ENABLED` | `true` = Redis Lua + MQ 异步下单；`false` = 降级 Redisson 分布式锁（用于对比压测） |
| `BACKEND_JAVA_OPTS` | JVM 参数，2C4G 保持默认 `-Xms512m -Xmx1024m`；2C2G 建议改 `-Xms256m -Xmx640m` |
| `KNIFE4J_ENABLE` | 是否开放 Knife4j 接口文档，生产建议 `false` |

### 7.3 收紧文件权限

```bash
chmod 600 .env.prod
```

> `.env.prod` 已在 `.gitignore` 中，切勿提交到仓库。

## 8. 第 7 步：一键部署

### 8.1 执行部署脚本

```bash
cd /opt/smartlife
./scripts/deploy.sh --first
```

这个脚本会按顺序做 5 件事：

1. 校验环境（Docker / Compose 插件 / `.env.prod` 是否还有 `CHANGE_ME` / 可用内存 ≥ 1.5G）
2. 构建镜像：`docker compose build --pull`
3. 启动全部容器：`docker compose up -d`
4. 轮询等待前端 80 端口可用（最多 180 秒）
5. 调用登录接口验证后端就绪，并打印三端访问地址与演示账号

> **首次构建耗时**：取决于带宽，通常 5~15 分钟。这一步会在容器内下载 Maven 依赖（约 200MB）和 npm 依赖（约 300MB）并编译前后端，请耐心等待，不要中断。

如果你不想用脚本，等价的原始命令是：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build
```

### 8.2 观察启动过程（可选，另开一个 SSH 窗口）

```bash
cd /opt/smartlife
docker compose --env-file .env.prod -f docker-compose.prod.yml ps        # 容器状态
docker compose --env-file .env.prod -f docker-compose.prod.yml logs -f backend
```

后端启动成功的日志长这样（`Started SmartLifeApplication in x.x seconds`）：

```
2026-09-12 15:40:12.345  INFO 1 --- [main] c.s.SmartLifeApplication : Started SmartLifeApplication in 18.732 seconds
2026-09-12 15:40:12.456  INFO 1 --- [main] c.s.init.DataInitRunner  : 索引初始化完成：布隆过滤器 + GEO 装载 10 家可展示店铺
```

按 `Ctrl + C` 退出日志跟随（**不会**停止容器）。

### 8.3 容器状态期望值

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml ps
```

```
NAME                  STATUS                    PORTS
smartlife-backend     Up (healthy)              127.0.0.1:8080->8080/tcp
smartlife-frontend    Up (healthy)              0.0.0.0:80->80/tcp
smartlife-mysql       Up (healthy)              127.0.0.1:3306->3306/tcp
smartlife-rabbitmq    Up (healthy)              127.0.0.1:5672->5672/tcp, 127.0.0.1:15672->15672/tcp
smartlife-redis       Up (healthy)              127.0.0.1:6379->6379/tcp
```

**关键点**：只有 `frontend` 的 PORTS 是 `0.0.0.0:80`，其余全是 `127.0.0.1` —— 说明除网站外都没有对公网暴露。

## 9. 第 8 步：验证验收清单

| 商家端（待审核） | `13700000002` | `merchant123` | 进入商家端后提示"店铺尚未开通经营权限"，可在「店铺与入驻」看到待审核申请 |

### 9.3 端侧权限验收（重点，最能说明三端隔离成功）

用**商家账号**登录后，在浏览器地址栏手动输入 `http://<IP>/admin/dashboard` → 会被前端路由守卫弹回商家端；
再用 Chrome DevTools Console 直接调接口模拟越权：

```javascript
// 在用户端页面（已登录用户账号）的控制台执行
fetch('/api/admin/stats/overview', {
  headers: { Authorization: 'Bearer ' + JSON.parse(localStorage.getItem('sl_user')).token }
}).then(r => r.json()).then(console.log)
// 期望输出：{code: 403, msg: "该接口仅平台管理员可访问"}
```

## 12. 升级与回滚

### 12.1 升级（代码更新后）

```bash
cd /opt/smartlife
git pull                       # 方式 A 部署时；方式 B 需重新上传覆盖
./scripts/deploy.sh            # 重新构建 + 滚动启动 + 健康检查
```

只有改动过的层会重新构建（Docker 层缓存），通常 1~3 分钟。

### 12.2 回滚

镜像打了版本 tag（`APP_VERSION`），回滚分两种情况：

**情况一：只是代码回滚**

```bash
cd /opt/smartlife
git log --oneline -5           # 找到上一个可用提交
git checkout <上一个提交的hash>
./scripts/deploy.sh
```

**情况二：数据库结构也变了，需要连数据一起回滚**

```bash
cd /opt/smartlife
./scripts/restore-db.sh backup/smartlife_<升级前的备份>.sql.gz
git checkout <上一个提交的hash>
./scripts/deploy.sh
```

> 因此**每次升级前先跑一次 `./scripts/backup-db.sh`** 是好习惯。

### 12.3 从旧版（双端）数据库升级到三端

如果你之前已经部署过旧版本（`role` 只有 1=用户、2=管理员，没有商家表），**不要**重跑 `init.sql`（`INSERT IGNORE` 不会覆盖已有数据，但新表新列也不会补全）。正确做法是执行幂等升级脚本：

```bash
cd /opt/smartlife
dc exec -T mysql mysql -uroot -p"$(grep MYSQL_ROOT_PASSWORD .env.prod | cut -d= -f2)" smartlife \
  < sql/manual/upgrade_v2_three_end.sql
```

脚本做的事：原 `role=2` 管理员自动提升为 `role=3`；给 `tb_user` 加 `status`；给 `tb_shop` 加 `merchant_id/audit_status/open_status/...`；给 `tb_voucher` 加 `audit_status`；新建 `tb_merchant_apply`、`tb_audit_log`；为历史店铺补建商家账号（`13700000001~10 / merchant123`）并绑定归属。脚本可重复执行。

## 13. 架构与端口说明

### 13.1 端口清单

| 端口 | 容器 | 绑定地址 | 是否需安全组放行 | 说明 |
|---|---|---|---|---|
| 80 | frontend | `0.0.0.0` | ✅ 需要 | 网站入口（可改 `HTTP_PORT`） |
| 8080 | backend | `127.0.0.1` | ❌ 不需要 | Spring Boot API（context-path=`/api`） |
| 3306 | mysql | `127.0.0.1` | ❌ 不需要 | 数据库，仅运维隧道使用 |
| 6379 | redis | `127.0.0.1` | ❌ 不需要 | 缓存 / GEO / 秒杀库存 |
| 5672 | rabbitmq | `127.0.0.1` | ❌ 不需要 | AMQP 协议端口 |
| 15672 | rabbitmq | `127.0.0.1` | ❌ 不需要 | RabbitMQ 管理台 |

### 13.2 请求链路

```
浏览器 http://IP/user/home
  → frontend:80 (Nginx) 命中 try_files → 返回 index.html（Vue 应用）
  → Vue 发起 XHR /api/shop/list?page=1
  → Nginx location /api/ → proxy_pass http://backend:8080/api/
  → Spring Boot AuthInterceptor 校验 JWT → Controller → Service → MySQL/Redis
  → 返回 {code:1,msg:"ok",data:[...]} → 前端渲染

WebSocket：浏览器 ws://IP/api/ws?token=xxx
  → Nginx location /api/ws（Upgrade/Connection 头）→ backend:8080/api/ws
  → WsHandshakeInterceptor 校验 token → 按角色分桶注册会话
  → 用户支付成功时，后端只推给该店铺的商家（NEW_ORDER）
```

### 13.3 数据库初始化行为（重要，避免误解）

- `sql/init.sql` 通过 compose 挂载到 MySQL 容器的 `/docker-entrypoint-initdb.d/01-init.sql`。
- MySQL 官方镜像**只在数据目录为空时**执行该目录下的脚本。也就是说：
  - 首次部署 → 自动建库建表 + 写入三端种子数据 ✅
  - 以后重启/重新部署 → **不会**重复执行，数据保持原样 ✅
- 想彻底重置数据库（清空所有业务数据重新初始化）：

```bash
cd /opt/smartlife
dc down
docker volume rm smartlife-mysql-data
dc up -d
```

## 14. 安全加固建议

按重要性排序，建议至少做前 4 条：

1. **改掉全部默认密码**：`.env.prod` 里的 4 个密钥必须是随机强密码（第 7 步已生成），并确保没有 `CHANGE_ME` 残留：
   ```bash
   grep -n CHANGE_ME .env.prod    # 应无输出
   ```
2. **生产关闭接口文档**：`KNIFE4J_ENABLE=false`（默认已是），避免接口结构对外暴露。
3. **限制 SSH 来源**：安全组把 22 端口的授权对象从 `0.0.0.0/0` 改成你的固定办公/家庭 IP；或改用密钥对登录并禁用密码登录：
   ```bash
   vim /etc/ssh/sshd_config     # PasswordAuthentication no
   systemctl restart sshd
   ```
4. **定期更新系统与镜像**：
   ```bash
   apt-get update && apt-get -y upgrade
   cd /opt/smartlife && docker compose --env-file .env.prod -f docker-compose.prod.yml pull
   ```
5. **启用阿里云云监控告警**：对 CPU、内存、磁盘使用率设置告警阈值（如磁盘 > 80%）。
6. **不要用 root 跑日常操作**：创建普通用户 + sudo，root 仅用于部署。
7. **给关键业务加限流**（进阶）：目前秒杀接口靠 Redis Lua + 一人一单兜底；若要对外压测，建议在 Nginx 层加 `limit_req` 或在网关做 IP 限流。

## 15. 后续：接入域名与 HTTPS

无域名时 `http://IP/` 已完全可用。等你买了域名（需备案才能解析到国内 ECS），可按下面步骤升级：

### 15.1 解析域名

阿里云「云解析 DNS」→ 添加记录：`A` 记录，主机记录 `@`（或 `www`），记录值 = ECS 公网 IP。

### 15.2 修改 Nginx 配置支持域名

编辑 `frontend/nginx.conf`，把 `server_name _;` 改成你的域名：

```nginx
server_name your-domain.com www.your-domain.com;
```

### 15.3 申请免费 SSL 证书并启用 HTTPS

1. 阿里云「数字证书管理服务」→ 申请免费 DV 证书 → 下载 **Nginx 版**，得到 `.pem` 与 `.key` 两个文件。
2. 上传到服务器 `/opt/smartlife/certs/`。
3. 在 `docker-compose.prod.yml` 的 frontend 服务里挂载证书目录，并放行 443：

```yaml
  frontend:
    ports:
      - "${HTTP_PORT:-80}:80"
      - "443:443"
    volumes:
      - ./certs:/etc/nginx/certs:ro
```

4. 在 `frontend/nginx.conf` 增加 443 server 块（并将 80 端口改为跳转 HTTPS）：

```nginx
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name your-domain.com;

    ssl_certificate     /etc/nginx/certs/your-domain.pem;
    ssl_certificate_key /etc/nginx/certs/your-domain.key;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    # 以下 location 块与现有 http 配置完全一致，直接复用
    root /usr/share/nginx/html;
    index index.html;
    # ...（把原配置中的 location /、/api/、/api/ws、/assets/ 等复制过来）
}
```

5. 重新构建前端并放行 443 安全组：

```bash
cd /opt/smartlife
./scripts/deploy.sh
```

> 前端 WebSocket 会自动跟随页面协议：`http` 页面用 `ws://`，`https` 页面自动用 `wss://`（见 `frontend/src/utils/ws.js`），无需改代码。

## 16. 性能调优（升配后）

当服务器升到 4C8G 以上、或要对外压测时，可按需调整：

| 项目 | 位置 | 默认 | 建议 |
|---|---|---|---|
| JVM 堆 | `.env.prod` 的 `BACKEND_JAVA_OPTS` | `-Xmx1024m` | 4G 内存可到 `-Xmx2048m`；8G 可到 `-Xmx4096m` |
| MySQL 缓冲池 | `docker-compose.prod.yml` 的 mysql command | `innodb-buffer-pool-size=512M` | 内存 8G 可提到 `2G` |
| MySQL 连接数 | 同上 | `max_connections=500` | 一般无需调整 |
| Redis 内存上限 | 同上 | `maxmemory 512mb` | 数据量大时提升；注意策略是 `noeviction`（缓存淘汰会破坏秒杀库存正确性，故不设为 LRU） |
| HikariCP 连接池 | `application.yml` | `maximum-pool-size=20` | 并发高可到 `30~50` |
| Nginx 静态缓存 | `frontend/nginx.conf` | `assets` 缓存 1 年 | 已优化，无需改 |
| 多实例扩容 | — | 单实例 | 后端无状态（JWT + ThreadLocal），可直接水平扩容，定时任务用 Redisson 锁互斥 |

秒杀方案对比压测（简历/面试常问）：

```bash
# 用 Redisson 锁方案（对照组）
sed -i 's/^SECKILL_LUA_ENABLED=.*/SECKILL_LUA_ENABLED=false/' .env.prod
dc up -d backend

# 切回 Lua + MQ 方案
sed -i 's/^SECKILL_LUA_ENABLED=.*/SECKILL_LUA_ENABLED=true/' .env.prod
dc up -d backend
```

## 17. 故障排查 FAQ

### Q1. 执行 `./scripts/deploy.sh --first` 卡在构建，或提示 `Killed`

**原因**：内存不足，Maven/npm 构建被 OOM Killer 杀掉。
**解决**：按第 4.3 节加 2G Swap；或先把 `.env.prod` 的 `BACKEND_JAVA_OPTS` 降到 `-Xmx640m`；实在不行在本地构建好 jar 与 dist 后只上传产物（见下方 Q2）。

### Q2. 想跳过服务器上的构建，直接用本地构建产物

```bash
# 本地：后端打 jar，前端打 dist
cd backend && mvn clean package -DskipTests
cd ../frontend && npm install && npm run build
# 上传 backend/target/*.jar 与 frontend/dist 到服务器对应目录，
# 然后把 backend/Dockerfile 换成"只拷贝 jar"的单阶段版本即可
```

### Q3. 容器起来了，但浏览器访问 `http://IP/` 一直转圈或超时

按顺序排查：

```bash
# 1) 容器是否在跑
dc ps
# 2) 服务器本机能否访问（排除 Nginx 自身问题）
curl -I http://127.0.0.1/
# 3) 安全组是否放行了 80（第 2.1 节）
# 4) 服务器防火墙是否拦了（ufw/iptables）
ufw status 2>/dev/null || iptables -L INPUT -n | head
```

若本机 `curl` 通、公网不通 → 一定是**安全组**问题（阿里云控制台改完立即生效）。

### Q4. 后端日志报 `Communications link failure` / `Connection refused: mysql`

**原因**：后端比 MySQL 先就绪。
**解决**：compose 已配置 `depends_on: condition: service_healthy`，正常不会出现。若仍出现，重启一次：

```bash
dc restart backend
```

### Q5. 登录接口返回 `服务器繁忙，请稍后再试`

统一异常兜底提示，真实原因在后端日志里：

```bash
dc logs --tail=200 backend | grep -A 20 ERROR
```

常见原因：数据库表缺失（初始化脚本没执行成功 → 见 13.3 节重置数据卷）、或 Redis/RabbitMQ 连接失败。

### Q6. 秒杀点击后没反应 / 报"手慢了"

排查顺序：

```bash
# 1) RabbitMQ 是否健康（秒杀是异步下单，MQ 不通会失败）
dc ps rabbitmq
# 2) Redis 里秒杀库存是否存在
dc exec redis redis-cli -a "$(grep REDIS_PASSWORD .env.prod|cut -d= -f2)" keys 'seckill:stock:*'
# 3) 券的时间窗（管理端/商家端编辑券即可同步刷新 Redis 库存）
```

> 秒杀券种子的时间窗是 `NOW-1天 ~ NOW+7天`，任何时候部署都能直接演示；超过 7 天后在商家端「优惠券管理」里改一下起止时间即可。

### Q7. "附近店铺"为空

登录用户端后，浏览器定位被拒绝时会回退到**北京望京**默认坐标，而种子店铺全在北京（经纬度 116.3~116.5 / 39.89~40.0），所以正常情况下应该能看到 10 家。若为空：

```bash
# 检查 Redis GEO 索引是否写入
dc exec redis redis-cli -a "$(grep REDIS_PASSWORD .env.prod|cut -d= -f2)" zcard shop:geo:0
# 期望返回 10；若为 0，重启后端触发索引重建（DataInitRunner）
dc restart backend
```

### Q8. WebSocket 连不上，商家端收不到新订单提醒

```bash
# 1) 确认 Nginx 的 ws location 生效（容器内查看配置）
dc exec frontend cat /etc/nginx/conf.d/default.conf | grep -A 8 'location /api/ws'
# 2) 确认浏览器 Console 里的 ws 地址是 ws://IP/api/ws?token=...
# 3) 若前面加了 HTTPS/代理，确认代理也放行了 Upgrade 头
```

### Q9. 磁盘满了

```bash
df -h
docker system prune -f            # 清理无用镜像/构建缓存（安全）
du -sh /var/lib/docker/volumes/*  # 找出大卷
# MySQL 数据 + 后端日志是主要增长源，可调小日志：application.yml 的 max-file-size/max-history
```

### Q10. 如何完全卸载并重来

```bash
cd /opt/smartlife
dc down -v                    # 删容器 + 数据卷（数据全丢！）
docker rmi smartlife-backend:2.0.0 smartlife-frontend:2.0.0
docker builder prune -f
```

## 附：最短路径速查（TL;DR）

```bash
# 0) 阿里云安全组放行 80 与 22
# 1) 登录服务器
ssh root@<公网IP>

# 2) 初始化
apt-get update && apt-get -y upgrade
apt-get install -y curl git unzip vim cron
timedatectl set-timezone Asia/Shanghai
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

# 3) 安装 Docker
curl -fsSL https://get.docker.com | bash -s docker --mirror Aliyun
systemctl enable docker --now

# 4) 放代码 + 配密钥
mkdir -p /opt && cd /opt && git clone <仓库地址> smartlife && cd smartlife
cp .env.prod.example .env.prod
sed -i "s|CHANGE_ME_mysql_root_strong_password|$(openssl rand -base64 24)|" .env.prod
sed -i "s|CHANGE_ME_redis_strong_password|$(openssl rand -base64 24)|" .env.prod
sed -i "s|CHANGE_ME_rabbitmq_strong_password|$(openssl rand -base64 24)|" .env.prod
sed -i "s|CHANGE_ME_jwt_secret_at_least_32_bytes_long_random_string|$(openssl rand -base64 36)|" .env.prod
chmod 600 .env.prod && chmod +x scripts/*.sh

# 5) 部署
./scripts/deploy.sh --first

# 6) 访问
#   http://<公网IP>/            用户端（13900000001 / 123456）
#   http://<公网IP>/merchant    商家端（13700000001 / merchant123）
#   http://<公网IP>/admin       管理端（13800000000 / admin123）
```
