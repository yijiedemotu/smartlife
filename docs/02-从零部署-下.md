# 阶段 6 · 启动服务

### 执行（整段粘贴）

```bash
cd /opt/smartlife
DC="docker compose --env-file .env.prod -f docker-compose.prod.yml"

echo "=== 6.1 启动 ==="
$DC up -d

echo
echo "=== 6.2 等待就绪（最多 180 秒）==="
for i in $(seq 1 36); do
  sleep 5
  RUNNING=$($DC ps --format '{{.Service}} {{.State}}' | grep -c 'running')
  HEALTHY=$($DC ps --format '{{.Service}} {{.Health}}' | grep -c 'healthy')
  printf '  第 %3d 秒：running=%s  healthy=%s\n' "$((i*5))" "$RUNNING" "$HEALTHY"
  if [ "$RUNNING" -ge 5 ] && [ "$HEALTHY" -ge 4 ]; then echo "  → 已就绪"; break; fi
done

echo
echo "=== 6.3 最终容器状态 ==="
$DC ps

echo
echo "=== 6.4 端口暴露（关键：只有 frontend 应为 0.0.0.0:80）==="
$DC ps --format '{{.Service}}\t{{.Ports}}'
```

# 阶段 7 · 三端功能验收（命令行）

**目的**：不依赖浏览器，先用接口把"三端权限、数据隔离、治理闭环"验证一遍。
**这几条正是这个项目区别于普通 CRUD 项目的核心能力。**

### 执行（整段粘贴）

```bash
cd /opt/smartlife
API=http://127.0.0.1/api

echo "=== 7.1 前端页面可达（应都是 200）==="
curl -s -o /dev/null -w "  /          -> %{http_code}\n" http://127.0.0.1/
curl -s -o /dev/null -w "  /login     -> %{http_code}\n" http://127.0.0.1/login
curl -s -o /dev/null -w "  /merchant  -> %{http_code}\n" http://127.0.0.1/merchant/dashboard
curl -s -o /dev/null -w "  /admin     -> %{http_code}\n" http://127.0.0.1/admin/dashboard

echo
echo "=== 7.2 三端登录（关键字段）==="
for acc in "13800000000:admin123:管理端" "13700000001:merchant123:商家(已过审)" "13700000002:merchant123:商家(待审核)" "13900000001:123456:用户端"; do
  PHONE=${acc%%:*}; REST=${acc#*:}; PWD=${REST%%:*}; NAME=${REST#*:}
  RESP=$(curl -s -X POST $API/auth/login -H 'Content-Type: application/json' \
         -d "{\"phone\":\"$PHONE\",\"password\":\"$PWD\"}")
  ROLE=$(echo "$RESP" | grep -o '"role":[0-9]*' | cut -d: -f2)
  HOME=$(echo "$RESP" | grep -o '"homePath":"[^"]*"' | cut -d'"' -f4)
  SHOP=$(echo "$RESP" | grep -o '"shopId":[0-9]*' | cut -d: -f2)
  CODE=$(echo "$RESP" | grep -o '"code":[0-9]*' | cut -d: -f2)
  printf '  %-16s code=%s role=%s homePath=%-24s shopId=%s\n' "$NAME" "$CODE" "$ROLE" "$HOME" "${SHOP:--}"
done

echo
echo "=== 7.3 用户端店铺列表（应 10 家）==="
UTOK=$(curl -s -X POST $API/auth/login -H 'Content-Type: application/json' \
       -d '{"phone":"13900000001","password":"123456"}' | sed -n 's/.*"token":"\([^"]*\)".*/\1/p')
SHOPS=$(curl -s "$API/shop/list?page=1&size=50" -H "Authorization: Bearer $UTOK")
echo "  返回店铺数：$(echo "$SHOPS" | grep -o '"id"' | wc -l)"
echo "  首条：$(echo "$SHOPS" | head -c 120)..."

echo
echo "=== 7.4 越权拦截（用户 token 调管理端，应 code:403）==="
curl -s "$API/admin/stats/overview" -H "Authorization: Bearer $UTOK" | head -c 160; echo

echo
echo "=== 7.5 未登录访问受保护接口（应 code:401）==="
curl -s "$API/order/mine" | head -c 160; echo

echo
echo "=== 7.6 商家数据隔离（商家 token 强查别家店铺 shopId=2，应被拒）==="
MTOK=$(curl -s -X POST $API/auth/login -H 'Content-Type: application/json' \
       -d '{"phone":"13700000001","password":"merchant123"}' | sed -n 's/.*"token":"\([^"]*\)".*/\1/p')
curl -s "$API/merchant/product/list?page=1&size=5&shopId=2" -H "Authorization: Bearer $MTOK" | head -c 160; echo

echo
echo "=== 7.7 商家端看板（应 code:1 且带 shopName）==="
curl -s "$API/merchant/dashboard/overview" -H "Authorization: Bearer $MTOK" | head -c 260; echo

echo
echo "=== 7.8 管理端平台看板（应 code:1 且含 totalUsers/totalMerchants）==="
ATOK=$(curl -s -X POST $API/auth/login -H 'Content-Type: application/json' \
       -d '{"phone":"13800000000","password":"admin123"}' | sed -n 's/.*"token":"\([^"]*\)".*/\1/p')
curl -s "$API/admin/stats/overview" -H "Authorization: Bearer $ATOK" | head -c 300; echo
```

### ✅ 通过标准

| 项 | 期望 |
|---|---|
| 7.1 | 4 个都是 `200` |
| 7.2 | 管理端 `role=3 homePath=/admin/dashboard`；商家1 `role=2 shopId=1`；商家2 `role=2 shopId=-`（未开店，shopId 为空）；用户 `role=1 homePath=/user/home` |
| 7.3 | 店铺数 = `10` |
| 7.4 | 含 `"code":403` |
| 7.5 | 含 `"code":401` |
| 7.6 | `"code":0` 或被拒（不得返回店铺 2 的商品） |
| 7.7 | `"code":1` 且含 `"shopName"` |
| 7.8 | `"code":1` 且含 `totalUsers`、`totalMerchants`、`pendingApplies` |

# 阶段 8 · 浏览器实测

> **前置条件**：阿里云安全组已放行 **80 端口**（入方向，授权对象 `0.0.0.0/0`）。
> 如果浏览器打不开但阶段 7.1 的 `curl` 是 200，那一定是安全组问题——**先查安全组，不要改代码**。

### 8.1 先确认安全组放行

阿里云控制台 → ECS → 实例 → 安全组 → 访问规则 → 入方向，确保有：

| 协议 | 端口 | 授权对象 |
|---|---|---|
| TCP | 80/80 | 0.0.0.0/0 |
| TCP | 22/22 | 0.0.0.0/0（或你的 IP） |

### 8.2 浏览器打开（把 IP 换成你的公网 IP）

| 端 | 地址 | 账号 / 密码 | 应该看到 |
|---|---|---|---|
| 用户端 | `http://你的IP/` | `13900000001` / `123456` | 自动跳到 `/user/home`，10 家北京店铺 |
| 商家端 | `http://你的IP/merchant` | `13700000001` / `merchant123` | 左侧「蜀香居川菜馆 · 营业中」，看板有图表 |
| 商家端（待审核） | `http://你的IP/merchant` | `13700000002` / `merchant123` | 提示"店铺尚未开通经营权限" |
| 管理端 | `http://你的IP/admin` | `13800000000` / `admin123` | 平台看板 + 「入驻审核」角标显示 1 |

### 8.3 越权验证（前端守卫 + 后端拦截）

1. 用**商家账号**登录后，地址栏手动输入 `http://你的IP/admin/dashboard` → 应被弹回商家端。
2. 用**用户账号**登录后，F12 Console 执行：

```javascript
fetch('/api/admin/stats/overview', {
  headers: { Authorization: 'Bearer ' + JSON.parse(localStorage.getItem('sl_user')).token }
}).then(r => r.json()).then(console.log)
// 期望：{code: 403, msg: "该接口仅平台管理员可访问"}
```

### 8.4 完整演示脚本：10 秒讲清"三端联动"

1. **用户端**（`13900000001`）在「蜀香居川菜馆」下单 → 支付；
2. 切到**商家端**（`13700000001`）→ 右下角弹「🔔 新订单提醒」→ 订单履约里接单 → 配送 → 完成；
3. 切到**管理端**（`13800000000`）→ 平台看板今日订单/GMV 有数据 → 「审计日志」能看到操作留痕；
4. **治理闭环**：用 `13700000002` 登录商家端（提示未开通）→ 管理端「入驻审核」点通过 → 再登录 `13700000002`，店铺已自动开通、可上架商品。

### ✅ 通过标准

- 四个端都能正常打开并登录，页面无白屏、无 `500`
- 8.3 的两处越权都被拦住
- 8.4 的四步都能走通（尤其第 2 步的**新订单弹窗只出现在对应店铺**）

# 阶段 9 · 日常运维便捷命令

**目的**：以后不用每次 `cd` 和敲一长串 compose 命令。

### 执行

```bash
cd /opt/smartlife

# 1) 安装全局便捷命令 sl
cat > /usr/local/bin/sl <<'EOF'
#!/usr/bin/env bash
# 智联生活运维便捷命令：任意目录下使用
#   sl ps / sl logs -f backend / sl restart backend / sl up -d / sl down
cd /opt/smartlife || { echo "项目目录 /opt/smartlife 不存在"; exit 1; }
exec docker compose --env-file .env.prod -f docker-compose.prod.yml "$@"
EOF
chmod +x /usr/local/bin/sl

# 2) 安装部署脚本的执行位
chmod +x scripts/*.sh

# 3) 再加两个快捷方式
cat > /usr/local/bin/sl-logs <<'EOF'
#!/usr/bin/env bash
cd /opt/smartlife && exec docker compose --env-file .env.prod -f docker-compose.prod.yml logs -f --tail=200 "${1:-backend}"
EOF
cat > /usr/local/bin/sl-backup <<'EOF'
#!/usr/bin/env bash
cd /opt/smartlife && exec ./scripts/backup-db.sh "$@"
EOF
chmod +x /usr/local/bin/sl-logs /usr/local/bin/sl-backup
```

### 执行校验

```bash

echo
echo "=== 9.2 日志命令 ==="
sl-logs backend | head -3

echo
echo "=== 9.3 部署脚本状态 ==="
cd /opt/smartlife && ls -l scripts/*.sh
```

### ✅ 通过标准

| 项 | 期望 |
|---|---|
| 9.1 | 列出 5 个容器，全部 Up |
| 9.2 | 能打印出后端日志前几行 |
| 9.3 | `scripts/*.sh` 都是 `-rwxr-xr-x` |


## 10.5 密码轮换（唯一正确姿势）

> **`MYSQL_ROOT_PASSWORD` 只在数据卷第一次初始化时生效。** 只改 `.env.prod` 不删数据卷 = 后端连不上库。

```bash
cd /opt/smartlife
docker compose --env-file .env.prod -f docker-compose.prod.yml down -v    # 删容器 + 数据卷（数据清空）
sed -i "s|^MYSQL_ROOT_PASSWORD=.*|MYSQL_ROOT_PASSWORD=$(openssl rand -base64 24)|" .env.prod
sed -i "s|^REDIS_PASSWORD=.*|REDIS_PASSWORD=$(openssl rand -base64 24)|" .env.prod
sed -i "s|^RABBIT_PASSWORD=.*|RABBIT_PASSWORD=$(openssl rand -base64 24)|" .env.prod
sed -i "s|^JWT_SECRET=.*|JWT_SECRET=$(openssl rand -base64 36)|" .env.prod
chmod 600 .env.prod
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d
# 数据卷已重建 → init.sql 会重新执行 → 三端种子数据恢复
```

⚠️ 这会**清空业务数据**。有真实数据时先导出（`./scripts/backup-db.sh`）再还原。

## 排错手册（按症状查）

| 症状 | 根因 | 处理 |
|---|---|---|
| `couldn't find env file: /root/.env.prod` | 工作目录不对（SSH 登录默认在 `/root`） | `cd /opt/smartlife` 后再执行 |
| `./scripts/deploy.sh: Permission denied` | 脚本缺执行位（Windows 打包常见） | `bash scripts/verify-package.sh --fix` 或 `chmod +x scripts/*.sh` |
| `bad interpreter: /bin/bash^M` | 脚本被 CRLF 污染 | `sed -i 's/\r$//' scripts/*.sh`（或 `verify-package.sh --fix`） |
| 构建报 `"/settings.xml": not found` | `backend/.dockerignore` 误排除 | `sed -i '/^settings\.xml$/d' backend/.dockerignore` 后重建 |
| 构建被 `Killed` | 内存不足 | 确认 Swap ≥ 2G（阶段 1.2）；或把 `.env.prod` 里 `BACKEND_JAVA_OPTS` 降到 `-Xmx640m` |
| 登录报"服务器繁忙" | 后端异常，需看日志 | `sl logs --tail=80 backend` 找 `ERROR`；常见是 DB 未就绪或密码不一致 |
| 登录报"账号或密码错误" | 种子数据未写入 | `sl exec mysql mysql -uroot -p<密码> -e "USE smartlife; SELECT COUNT(*) FROM tb_user;"`；为 0 说明数据卷非空但库是旧的 → 按 10.5 重置 |
| 浏览器打不开但 `curl 127.0.0.1` 通 | 安全组未放行 80 | 阿里云控制台安全组加 80 入方向 |
| 改了 `.env.prod` 密码后连不上库 | 数据卷里是旧密码 | 改回去，或按 10.5 连数据卷一起重置 |
| 秒杀提示"手慢了" | Redis 库存与 DB 不同步 | `sl restart backend`（启动会回填）；或商家端重存一次该券 |
| 附近店铺为空 | Redis GEO 索引未建 | `sl restart backend` 触发重建；用 `sl exec redis redis-cli -a <密码> zcard shop:geo:0` 应为 10 |
| WebSocket 收不到新订单 | Nginx 未透传升级头 | `sl exec frontend cat /etc/nginx/conf.d/default.conf \| grep -A5 '/api/ws'` |
| 磁盘满 | 镜像/日志/备份堆积 | `docker system prune -f`；`df -h`；清理旧 `backup/*.sql.gz` |
